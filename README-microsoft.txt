用 Microsoft 帳號寄詢價通知信
============================================================
做完之後：客戶送出表單 →
  1. 資料寫進 D1 的 inquiries 表（編輯頁的「客戶詢價」看得到）
  2. 從你的 Microsoft 信箱寄出內部通知信 + 客戶自動回覆

在設定完成之前，網站照樣正常運作 —— 資料一樣會存進 D1，
信會由原本的 Google Apps Script 寄出（前端會自己判斷）。
所以你可以先上傳部署，之後再慢慢弄 Microsoft 這段。


前提：需要 Microsoft 365 商業帳號
------------------------------------------------------------
必須是 Microsoft 365 / Exchange Online 的組織帳號
（@wpjk.inteplast.com 這種），而且註冊應用程式那一步需要
**管理員權限**。如果你不是 IT 管理員，把下面步驟 1-3 轉給
IT 同事，他們大概五分鐘就能做完，你只需要拿到三個值。

個人的 outlook.com 帳號不適用這個做法。


步驟 1｜註冊應用程式
------------------------------------------------------------
https://entra.microsoft.com
  → 應用程式 → 應用程式註冊 → 新增註冊

  名稱：INTEPLAST 官網寄信
  支援的帳戶類型：僅此組織目錄中的帳戶
  重新導向 URI：不用填

按「註冊」。完成後在「概觀」頁記下兩個值：
  應用程式（用戶端）ID   → 之後填 MS_CLIENT_ID
  目錄（租用戶）ID       → 之後填 MS_TENANT_ID


步驟 2｜給它寄信權限
------------------------------------------------------------
在同一個應用程式裡：
  → API 權限 → 新增權限 → Microsoft Graph
  → **應用程式權限**（不是委派的權限）
  → 搜尋 Mail.Send → 勾選 → 新增權限

回到列表，按上方的「**代表組織授予管理員同意**」。
狀態要變成綠色勾勾才算完成 —— 這一步一定要管理員按。

⚠ Mail.Send 應用程式權限預設可以寄「組織內任何信箱」的信。
   要限制只能用某一個信箱寄，請 IT 加一條 Exchange 的
   ApplicationAccessPolicy（下面「收尾建議」有說明）。


步驟 3｜建立用戶端密碼
------------------------------------------------------------
  → 憑證及密碼 → 用戶端密碼 → 新增用戶端密碼
  描述：Cloudflare Pages
  到期：24 個月（記下到期日，到期要換）

建立後那串「值」**只會顯示一次**，馬上複製起來
→ 之後填 MS_CLIENT_SECRET


步驟 4｜決定用哪個信箱寄
------------------------------------------------------------
需要一個真實存在的信箱（有授權的使用者或共用信箱），例如
  no-reply@wpjk.inteplast.com
或直接用 lyanchen@wpjk.inteplast.com

→ 之後填 MS_SENDER

註：收信人不在這裡設定 —— 通知信會寄到編輯頁「公司資訊」
    裡的聯絡信箱（含副本收件人），改那裡就會改收件人。


步驟 5｜填進 Cloudflare
------------------------------------------------------------
Workers & Pages → 你的專案 → 設定 → 變數與密鑰 → 新增

  MS_TENANT_ID       目錄（租用戶）ID        類型：純文字
  MS_CLIENT_ID       應用程式（用戶端）ID    類型：純文字
  MS_CLIENT_SECRET   用戶端密碼的「值」      類型：**密鑰**
  MS_SENDER          寄件信箱                類型：純文字

MS_CLIENT_SECRET 一定要選「密鑰（Secret）」—— 選純文字的話
任何能進 Dashboard 的人都看得到它。

Production 與 Preview 兩個環境都要填。填完**重新部署**。


步驟 6｜驗證
------------------------------------------------------------
1. 先跑 db/schema-v4.sql 建立 inquiries 表
2. 到網站的「聯繫我們」用自己的信箱送一筆測試
3. 編輯頁 → 客戶詢價 → 那筆應該出現，且沒有「通知信未寄出」標記
4. 你的公司信箱應該收到「【官網詢價】…」
5. 你填的那個信箱應該收到自動回覆

若那筆有「通知信未寄出」標記：資料已經存好了（不會漏客戶），
只是 Graph 那段失敗。常見原因：
  - Mail.Send 沒有按「管理員同意」（最常見）
  - 加成「委派的權限」而不是「應用程式權限」
  - MS_SENDER 那個信箱不存在或沒有授權
  - 用戶端密碼過期
四個環境變數改完都要重新部署才生效。


收尾建議（做完上面之後）
------------------------------------------------------------
1. 確認 Graph 這條穩定運作幾天後，可以把 contact.html 裡的
   Apps Script 備援移除，Google Sheet 那條線就完全退場。
   在那之前留著沒有壞處 —— 它只在 Graph 失敗時才會動。

2. 請 IT 限制寄件範圍（避免這組憑證能寄組織內任何人的信）：
   Exchange Online PowerShell 執行 New-ApplicationAccessPolicy，
   把應用程式限定在 MS_SENDER 那一個信箱。

3. 用戶端密碼到期前要換 —— 到期那天信就會停止寄出
   （資料仍會存進 D1，前端也會自動退回 Apps Script）。
