給 IT 的申請單 — 官網詢價表單寄信
============================================================
複製下面「要請 IT 做的事」整段給他們就好，不必解釋前因後果。


============================================================
要請 IT 做的事
============================================================

我們的公司官網（Cloudflare Pages）有一個「聯繫我們」表單，
需要在客戶送出後寄兩封信：

  1. 通知信 → 寄給我們業務
  2. 自動回覆 → 寄給客戶（確認已收到）

想使用 Microsoft Graph API 寄信（不是 SMTP，不需要開放 SMTP 中繼，
也不需要改任何 DNS 記錄）。需要協助建立一個應用程式註冊：

Entra ID（Azure AD）→ 應用程式註冊 → 新增註冊
  名稱：INTEPLAST Taiwan Website Mailer
  支援的帳戶類型：僅此組織目錄中的帳戶
  重新導向 URI：不需要

  API 權限 → 新增權限 → Microsoft Graph → 應用程式權限
    Mail.Send
  ★ 然後點選「代表組織授予管理員同意」

  憑證及密碼 → 新增用戶端密碼
    有效期限：24 個月（到期前要換，屆時會再麻煩一次）

需要一個寄件信箱（可以是共用信箱，不必是個人的）：
    建議 no-reply@wpjk.inteplast.com


完成後請提供這四項給我：
    1. 目錄 (租用戶) ID
    2. 應用程式 (用戶端) ID
    3. 用戶端密碼「值」   ← 不是「密碼識別碼」，
                            而且它只在建立當下看得到一次
    4. 確認可用的寄件信箱

★ 資安說明（IT 通常會問）：
  Mail.Send 應用程式權限預設可以代表租用戶內任何信箱寄信。
  若貴部門希望限縮，請一併設定「應用程式存取原則」
  (New-ApplicationAccessPolicy)，把這個應用程式限制成
  只能使用上面那一個寄件信箱。我們完全支持這樣做。


============================================================
拿到之後我要做的（不需要 IT）
============================================================

Cloudflare → Workers & Pages → 專案 → 設定 → 變數與密鑰
四個都要加，Production 與 Preview 都設：

  MS_TENANT_ID       目錄 (租用戶) ID          一般變數
  MS_CLIENT_ID       應用程式 (用戶端) ID      一般變數
  MS_CLIENT_SECRET   用戶端密碼「值」          ← 設成「密鑰 Secret」
  MS_SENDER          no-reply@wpjk.inteplast.com

★ MS_CLIENT_SECRET 一定要選 Secret（密鑰），不要選純文字 ——
  選純文字的話任何能進 Cloudflare 後台的人都看得到它，
  等於把公司的寄信權限攤在外面。

設完到「部署」重試部署。


============================================================
通知信收件人
============================================================

不是環境變數，在後台改：
  網站內容管理 → 公司資訊 → 聯絡信箱 → lyanchen@fpc.com.tw

多人收就用逗號分隔，或填「副本收件人」。
之後換人接手不必找工程師。

註：收件人可以是任何網域（fpc.com.tw 沒問題），
    只有「寄件者」必須是租用戶裡的信箱。


============================================================
驗證
============================================================

到網站的聯繫我們送出一筆測試（用你自己的信箱）：

  1. lyanchen@fpc.com.tw 收到通知信
  2. 你填的信箱收到自動回覆
  3. 後台 → 客戶詢價 有那一筆，而且沒有「通知信未寄出」的黃色標記

三項都過就完成了。

如果第 3 項出現黃色標記，把後台那筆的錯誤訊息或
Cloudflare 的 Functions 記錄貼給我 —— 常見原因是
沒按「授予管理員同意」，或密碼填成了「識別碼」而不是「值」。


============================================================
運作方式（給接手的人）
============================================================

客戶送出 → 先寫進 D1 的 inquiries 表 → 再寄信。

順序是刻意的：資料先落地，所以就算寄信整個壞掉，
客戶資料也不會遺失，後台「客戶詢價」照樣看得到，
只是那一筆會標「通知信未寄出」。

自動回覆會依客戶當時瀏覽的語言選中文／英文／日文，
內容寫在 functions/api/inquiry.js 的 BODIES。
新增語言就在那裡加一份，找不到對應語言會退回中文。
