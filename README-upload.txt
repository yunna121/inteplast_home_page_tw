多語言地基 — 上傳說明
============================================================

這一批做完之後：
  · 網站支援任意數量的語言（不再只有中／英）
  · 選單、按鈕、標題那些字改由後台管理，共 186 條
  · 後台可以用 AI 批次翻譯，人工校對

------------------------------------------------------------
步驟 1｜先跑 SQL
------------------------------------------------------------
Cloudflare → D1 → company-website → Console
把 db/schema-v6.sql 整份貼上，按 Execute。

會建立 ui_strings 表，並把現有頁面上的 186 條中文與 184 條英文
搬進資料庫。既有網站行為完全不變（英文仍由 HTML 提供）。

------------------------------------------------------------
步驟 2｜上傳檔案
------------------------------------------------------------
新增：
  db/schema-v6.sql
  functions/api/ui-strings.js          介面文字（公開讀取）
  functions/api/admin/translate.js     產品／時間軸的 AI 翻譯草稿
  functions/api/admin/translate-ui.js  介面文字的 AI 批次翻譯

覆蓋：
  admin/index.html                     多了「介面文字」頁
  src/site-lang.js                     改寫成支援任意語言
  functions/api/admin/data.js
  functions/api/admin/save.js
  index.html / about.html / contact.html
  sustainability.html / products/index.html
      （只改了防閃爍那三行，讓它認得日文等新語言）

上傳後等 Pages 部署完成。

------------------------------------------------------------
步驟 3｜驗證
------------------------------------------------------------
1. 開網站 → 語言鈕應該變成下拉選單（因為有三種語言了）
2. 切到 English → 一切如常（英文來自資料庫，內容跟以前一樣）
3. 切到 日本語 → 只有產品名稱等已翻譯的變日文，其餘仍是中文
   ← 這是正常的，還沒翻譯

------------------------------------------------------------
步驟 4｜翻譯日文
------------------------------------------------------------
後台 → 介面文字 → 日本語頁籤 → 按「用 AI 翻譯未完成的（186）」

會分批跑，畫面顯示進度，大約一兩分鐘。跑完之後逐條校對 ——
機器翻的一定有要改的地方，尤其是：
  · {{years}} 這種變數有沒有被吃掉
  · 公司名稱、Scale Sheet 等專有名詞有沒有被亂翻
  · 選單那幾條要夠短，太長會撐破版面

產品與時間軸的日文，到「產品資料」逐筆編輯 → 切到日本語頁籤
→ 按「用 AI 產生日本語草稿」→ 檢查後儲存。

------------------------------------------------------------
設計說明：為什麼用中文原文當鍵
------------------------------------------------------------
頁面上原本就有 data-tw="首頁"，那個「首頁」直接當索引鍵，
所以 186 條字串不必在 HTML 裡加任何 id —— 現有頁面一行都沒改。

同一句話在頁首與頁尾各出現一次，只會有一筆資料、翻一次就好
（實際上 218 處合併成 186 條）。

HTML 裡的 data-en 全部保留，當作資料庫還沒載入完或 API 掛掉時
的後備 —— 英文版在任何情況下都不會壞。
