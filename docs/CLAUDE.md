# 專案慣例

## 每次更新後直接給下載包
只要有檔案變動，收尾時就用 `present_fs_item_for_download` 直接給使用者一個下載包，不用等他要求。

- 把該次變動的檔案複製到暫存資料夾（例如 `更新包/`），保持與 repo 相同的資料夾結構，再打包給他
- 資料夾名稱只用英數與 `-`（中文路徑會被工具拒絕，例如 `update-pack/`）
- 標籤寫清楚檔案數與內容，例如「更新包（6 個檔案：頂欄品牌名修正）」
- 給完包後把暫存資料夾刪掉，不要留在專案裡
- 若變動包含 `src/` 下的程式或圖片，提醒他上傳時要把整個 `src` 資料夾拖進 GitHub（他上次只上傳到 `src/data` 那層，導致 repo 缺檔）

## 網站資料維護
- 唯一資料來源是 `src/data/website-data.xlsx`（工作表：產品規格／分類介紹／搜尋同義詞／說明），欄位只放商業資訊
- 技術對應（分類頁→頁面檔名、顏色名稱→色碼、張數＋包裝→顯示文字）寫在 `src/data-map.js`，不要放回 Excel
- 沒有伺服器時，改完 Excel 需用 `tools/update-specs.html` 轉出 `src/data/website-data.js`
