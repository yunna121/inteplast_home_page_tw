多語言網址（第一階段）
============================================================

做到什麼
------------------------------------------------------------
這三組網址都會運作，而且 Google 抓到的就是已經翻好的文字：

  https://inteplasttw.com.tw/about        中文
  https://inteplasttw.com.tw/en/about     English
  https://inteplasttw.com.tw/ja/about     日本語

不用複製 HTML、不用寫新內容。譯文沿用後台「介面文字」那 172 筆
（存在 D1 的 translations 表），中文改了其他語言自動跟著改。


要上傳的檔案（3 個）
------------------------------------------------------------
functions/_middleware.js    ← 覆蓋（原本的舊網址轉址功能完整保留）
sitemap.xml                 ← 覆蓋（5 頁 × 3 語言 = 15 個網址）
robots.txt                  ← 覆蓋

網頁檔案（HTML／CSS／JS）一個都不用改。


原理
------------------------------------------------------------
你的前端本來就是這樣換語言的：每個要翻譯的元素帶著 data-tw
（繁中原文），site-lang.js 拿 /api/ui-strings 回傳的對照表去查。

這支程式做同一件事，只是提早到伺服器端做完 —— 在 HTML 送出之前
就把 data-tw 的內容換成譯文。所以 Google 不必執行 JavaScript
就能讀到英文、日文。

同時處理的：
  · <html lang> 跟著語言走
  · title、description、og:／twitter: 分享卡換成對應語言
  · canonical 指向自己這個語言版（不然三個版本互相搶排名）
  · hreflang 互相指認，告訴 Google 這是同一頁的三個語言版本
  · 站內連結自動保留語言前綴，點進去不會掉回中文版


自動導向
------------------------------------------------------------
外國人開首頁時依瀏覽器語言導到 /en/ 或 /ja/。

三個保護：
  · 爬蟲不導 —— Googlebot 抓 / 被丟到 /en/ 的話，中文版就永遠
    收錄不到。這是這個功能最大的風險，所以特別處理
  · 用 302（暫時）不是 301（永久）
  · 中文與認不出來的語言留在中文版，不導

轉址回應標了 no-store，不然 Cloudflare 會把「導去英文」這個結果
快取起來，之後所有人都被導去英文。


怎麼測
------------------------------------------------------------
1) 開 inteplasttw.com.tw/en/about
   → 文字是英文、網址保持 /en/about（不是跳回中文）

2) 在那頁點「產品中心」
   → 網址應該是 /en/products/…，不是 /products/…

3) 開 inteplasttw.com.tw/ja/sustainability
   → 日文版

4) 檢視原始碼（Ctrl+U）搜 hreflang
   → 應該看到 zh-Hant-TW / en / ja / x-default 四行

5) 檢視原始碼確認**文字本身就是英文**
   → 這是關鍵。如果原始碼裡是中文、只有畫面上是英文，
     表示伺服器端替換沒生效，Google 還是看不到英文

6) 開 inteplasttw.com.tw/（中文版）
   → 確認沒有壞掉，而且原始碼裡也有 hreflang

7) 舊網址轉址還在運作
   → 開 inteplast-home-page-tw.pages.dev 應該被導到正式網域


部署後在 Search Console 要做的
------------------------------------------------------------
1) 重新送出 sitemap（Sitemap → 輸入 sitemap.xml）
2) 對 /en/ 與 /ja/ 各要求建立索引一次
3) 之後幾週在「產生索引 → 網頁」觀察 /en/ 與 /ja/ 有沒有被收錄


出問題時
------------------------------------------------------------
整支程式包在 try/catch 裡，出錯就當作沒事發生、照常放行中文版
—— 絕不會讓網站掛掉。

· /en/about 顯示 404
  → ASSETS 取不到 /about。確認 about.html 在根目錄
· /en/about 文字還是中文
  → /api/ui-strings 沒回傳譯文。直接開那個網址看有沒有 en 的值
· 譯文改了但沒更新
  → 對照表快取 5 分鐘，等一下再看
· 所有人都被導到英文
  → 快取問題。Cloudflare → Caching → Purge Everything


已知還沒做（第二、三階段）
------------------------------------------------------------
· 產品沒有各自的網址 —— 現在所有產品都在 /products/ 一頁裡，
  而且是瀏覽器才載入的，Google 很難把單一產品排上去。
  這是「搜 can liner 找到你」的關鍵，下一階段做。

· 日文的 title／description 還是中文 —— 頁面上只有 data-en，
  沒有 data-ja。第三階段連同關鍵字一起調。

· 導覽列與頁尾的文字仍由 JS 翻譯（那兩個是 JS 產生的）。
  不影響 SEO，因為選單文字不是排名依據。
